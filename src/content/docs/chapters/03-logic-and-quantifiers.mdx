## 本章目標

1. 看到一個邏輯符號，知道「要**證明**它」與「手上**有**它」時各該做什麼。
2. 能把課本上分情況、逆否、存在性的證明，一句一句翻成 Lean。
3. 看出量詞順序不同的兩個陳述，數學意義完全不同。

## 一個核心觀念：每個符號都有兩個動作

課本上的邏輯規則可以分成兩類。

- **引入**：怎麼「證明」一個含有這個符號的命題。例如要證「P 且 Q」，就分別證明 P 與 Q。
- **消去**：怎麼「使用」一個已知的、含有這個符號的命題。例如已知「P 且 Q」，就可以單獨拿出 P 來用。

Lean 的 tactic 幾乎一對一對應這兩類規則。所以卡住的時候，只要問自己兩個問題：**目標最外層是什麼符號？假設最外層是什麼符號？**

<Term term="tactic" short="證明裡的一個「動作」，例如「分成兩個子目標」或「交出現成的證據」。">

在 `by` 後面一行一行寫的指令就是 tactic。每執行一個 tactic，Lean 右側的 Infoview 就會顯示新的「目前已知」與「還要證明的目標」。tactic 不是魔法，它只是把課本上「我們接下來證明……」這類句子變成電腦能檢查的步驟。

</Term>

## 且：分別證明兩邊

先看最簡單的課本證明。左欄是你在離散數學作業上會寫的句子，右欄是對應的 Lean。

<PaperVsLean file="Course/University.lean" region="uni-and-intro" rows={["2", "3", "4", "5"]}>
  <Fragment slot="p1">**定理**：若 $P$ 成立且 $Q$ 成立，則 $P \land Q$ 成立。</Fragment>
  <Fragment slot="p2">要證明「且」，只需分別證明兩邊。</Fragment>
  <Fragment slot="p3">左邊 $P$：由假設直接得到。</Fragment>
  <Fragment slot="p4">右邊 $Q$：同樣由假設直接得到。證畢。</Fragment>
</PaperVsLean>

`constructor` 是「且」的引入：它把一個目標 `P ∧ Q` 拆成兩個目標 `P` 與 `Q`。開頭的 `·` 表示「現在處理其中一個目標」，讓結構和紙上的兩段一樣清楚。

反過來，如果「且」出現在**假設**裡，例如 `h : P ∧ Q`，那就用消去：`h.1` 是 `P` 的證據，`h.2` 是 `Q` 的證據；也可以寫 `obtain ⟨hp, hq⟩ := h` 一次拆開並命名。課程檔案中的 `and-swap` 就是先拆再組：

## 蘊含：先假設，再倒推

課本說「假設 $P$，要證 $R$」時，Lean 寫 `intro hp`。課本說「要證 $R$，只需證 $Q$（因為 $Q \Rightarrow R$）」時，Lean 寫 `apply`。下面把每一步之後 Infoview 的內容列出來，你可以和 VS Code 中實際看到的對照：

## 或：分情況證明

課本中「分情況討論」就是「或」的消去。已知「$P$ 或 $Q$」時，兩種情況都要推出結論。

<PaperVsLean file="Course/University.lean" region="uni-or-swap" rows={["2", "3", "4", "5-6", "7-8"]}>
  <Fragment slot="p1">**定理**：若 $P \lor Q$，則 $Q \lor P$。</Fragment>
  <Fragment slot="p2">假設 $P \lor Q$ 成立。</Fragment>
  <Fragment slot="p3">分兩種情況討論。</Fragment>
  <Fragment slot="p4">情況一：$P$ 成立。那麼 $Q \lor P$ 的**右邊**成立。</Fragment>
  <Fragment slot="p5">情況二：$Q$ 成立。那麼 $Q \lor P$ 的**左邊**成立。證畢。</Fragment>
</PaperVsLean>

注意 `left` 與 `right` 是「或」的引入：要證明 `Q ∨ P`，必須**選一邊**並交出那一邊的證據。選錯邊時 Lean 不會報錯，只會讓你卡在一個證不出來的目標上；這時請回到紙上想：在這個情況下，到底是哪一邊成立？

## 非：推出矛盾

在 Lean 裡，`¬ P` 的定義就是 `P → False`，意思是「如果 P 成立，就會矛盾」。所以證明 `¬ P` 和證明蘊含一樣，先 `intro`，再設法得到 `False`。課本上的**逆否證明**正好用到這件事：

<PaperVsLean file="Course/University.lean" region="uni-contrapositive" rows={["2", "3", "4"]}>
  <Fragment slot="p1">**定理**：若 $P \Rightarrow Q$，且 $Q$ 不成立，則 $P$ 不成立。</Fragment>
  <Fragment slot="p2">假設 $P \Rightarrow Q$、假設 $\lnot Q$，再假設 $P$ 成立，要推出矛盾。</Fragment>
  <Fragment slot="p3">由 $P$ 與 $P \Rightarrow Q$ 得到 $Q$，這和 $\lnot Q$ 矛盾。證畢。</Fragment>
</PaperVsLean>

`hpq hp` 是「把 P 的證據餵給 P → Q」，得到 Q 的證據；`hnq (hpq hp)` 再把它餵給 `Q → False`，得到 `False`。這就是「由 Q 與非 Q 得到矛盾」。

## 把剛才學到的整理成一張表

上面每個例子，其實都是在查同一張表。以後卡住時，回來這裡找「目標」或「假設」最外層的符號：

| 符號 | 目標是它時（引入：怎麼證明） | 假設中有它時（消去：怎麼使用） |
| --- | --- | --- |
| `p → q` | `intro hp` | `apply h` 或 `h hp` |
| `p ∧ q` | `constructor` | `obtain ⟨hp, hq⟩ := h` |
| `p ∨ q` | `left` 或 `right` | `rcases h with hp \| hq` |
| `¬ p` | `intro hp`（目標變成 `False`） | `exact h hp`（得到 `False`） |
| `False` | 通常無法直接證明 | `exact h.elim` 或 `contradiction` |
| `∀ x, P x` | `intro x` | `h a`（套用到特定的 `a`） |
| `∃ x, P x` | `use a` 或 `exact ⟨a, 證據⟩` | `obtain ⟨x, hx⟩ := h` |

## 量詞：「對所有」與「存在」

<Term term="見證（witness）" short="證明「存在某個 x」時，你實際拿出來的那個 x。">

課本上證明「存在 $m$ 使得……」時，我們會說「取 $m = n + 1$」。這個被取出來的 $m$ 就叫見證。在 Lean 中，存在性的證明就是一對東西：見證本身，加上「它確實滿足條件」的證據，寫成 `⟨見證, 證據⟩`。

</Term>

離散數學中的經典例子：「沒有最大的自然數」。課本的精確寫法是「對每個自然數 $n$，都存在 $m$ 使得 $n < m$」。

<PaperVsLean file="Course/University.lean" region="uni-no-largest" rows={["2", "3", "4"]}>
  <Fragment slot="p1">**定理**：$\forall n \in \mathbb{N},\ \exists m \in \mathbb{N},\ n < m$。</Fragment>
  <Fragment slot="p2">任取一個自然數 $n$。</Fragment>
  <Fragment slot="p3">取 $m = n + 1$，則 $n < n + 1$。證畢。</Fragment>
</PaperVsLean>

`intro n` 就是「任取 n」；`⟨n + 1, Nat.lt_succ_self n⟩` 就是「取 m = n + 1，而 `Nat.lt_succ_self n` 是 n < n + 1 的證據」。

再看一個把見證放在外層的例子：「存在一個實數 $x$，使得每個實數 $y$ 的平方都不小於 $x$」。見證是 $x = 0$，理由是平方非負：

<LeanCode file="Course/University.lean" region="uni-square-lower-bound" />

這裡 `refine ⟨0, ?_⟩` 的意思是「先交出見證 0，證據待會兒再補」。`?_` 會變成新的目標。

### 量詞順序是翻譯中最常見的錯誤

<QuantOrder />

課本口語常寫成「對所有 n 都有某個 m」，這句話可以讀成上圖左邊，也可以被誤讀成右邊。**檢查量詞順序是你的工作**：Lean 會接受兩個陳述都是合法命題，只是其中一個證不出來。AI 在翻譯這類句子時特別容易出錯，下面「和 AI 一起學」會實際練習。

## 反證法與排中律

課本中的反證法：「假設結論不成立，推出矛盾」。Lean 中可以直接用 `by_contra h`，它會把「結論的否定」放進假設，目標變成 `False`。

<details>
<summary>補充：為什麼有人說「P 或非 P」不能證明？（constructive 與 classical）</summary>

從上面的表看，要證明 `p ∨ ¬ p`，必須**選一邊**並交出證據。對一個我們一無所知的 p，只用引入與消去規則，無法決定該選哪一邊。這就是 **constructive**（構造式）邏輯的觀點：只用基本規則，排中律推不出來。

但 Lean 的標準函式庫加入了 `Classical.choice` 等標準公理，排中律因此是一個定理 `Classical.em : ∀ p, p ∨ ¬ p`。mathlib 的數學大量使用這種 classical 推理，`by_contra`、`by_cases` 都可以放心使用。所以正確說法是：「在不用 classical 公理的片段中不可證」，不能說成「Lean 不能證明排中律」。

想看具體例子，可以從 [AI101 第 6 集約 1:20](https://www.youtube.com/watch?v=Dqqh1G-CnL8&t=80s) 開始看，再對照下面兩個方向的雙重否定：

<LeanCode file="Course/VideoPractice.lean" region="double-negation" />

第一個方向只要把 `hP` 餵給 `hNotP` 就得到矛盾；反方向對任意命題要用 `Classical.byContradiction`。若在練習檔寫 `import Course.VideoPractice` 再執行 `#print axioms`，第二個定理會多出 `Classical.choice` 等標準公理，這是正常的，不是作弊。

</details>

> **查核提示**：Lean 接受一個證明，只代表「你寫下的陳述」被證明了。陳述的量詞順序與假設是否忠於課本，仍然要你自己看。

## 和 AI 一起學

<AskAI
  task="請 AI 把課本上的一句量詞敘述翻成 Lean，再由你檢查量詞順序。"
  prompt={"我在修離散數學。請把下面這句話翻成 Lean 4（mathlib）的陳述，先不要證明。\n句子：「對每個正整數 n，都存在一個質數 p 比 n 大。」\n請用中文逐一說明：\n1. 每個量詞（∀、∃）各對應原句哪幾個字；\n2. 量詞的順序為什麼是這樣；\n3. 「正整數」這個條件在 Lean 中放在哪裡。"}
>

- 量詞順序是不是「先 ∀ n，再 ∃ p」？如果 AI 寫成 `∃ p, ∀ n`，那就是上圖右邊那個錯誤的陳述。
- 「正整數」有沒有被寫進去（例如 `0 < n →`）？還是被默默拿掉了？在這題拿掉其實會讓陳述**更強**，請想想為什麼它仍然成立。
- 「質數」用的是 mathlib 的 `Nat.Prime` 嗎？請用 `#check Nat.Prime` 確認它真的存在。

### 真實紀錄：兩個 AI 怎麼翻「沒有最大的自然數」

我們把「沒有最大的自然數」這句話，原封不動交給兩個 AI，請它們翻成 Lean 並自行檢查。兩份結果都通過 Lean 編譯，但**選了不同的陳述**。

<AIDialogue tool="Claude Code" model="claude-opus-5-5" date="2026-10-12" result="通過獨立編譯，無錯誤、無警告。" record="quantifier/claude">

主定理採字面翻譯，另附一個正面說法：

```lean
theorem no_largest_nat : ¬ ∃ n : ℕ, ∀ m : ℕ, m ≤ n
theorem exists_larger_nat : ∀ n : ℕ, ∃ m : ℕ, n < m
```

> 這兩個定理之間的關係，正是離散數學裡的量詞否定規則：¬∃n ∀m (m ≤ n) ⟺ ∀n ∃m ¬(m ≤ n) ⟺ ∀n ∃m (n < m)

</AIDialogue>

<AIDialogue tool="Codex" model="gpt-6.1-sol（本機設定）" date="2026-10-12" result="通過獨立編譯，無錯誤、無警告。" record="quantifier/codex">

只寫正面說法：

```lean
theorem no_largest_natural_number : ∀ n : ℕ, ∃ m : ℕ, n < m
```

</AIDialogue>

**你該看出什麼？** 兩者都忠於原句，量詞順序也都正確。但要注意，Claude 說兩個定理「等價」，它其實是分別證明了兩個定理，**並沒有**在 Lean 中證明它們等價。那句「等價」是 AI 的數學說明，Lean 沒有檢查過。若要確認，你可以用本章的否定規則自己在紙上推一次，或在 Lean 中寫成 `↔` 再證明。這正是本課程反覆強調的分工：**Lean 檢查它被交付的定理；AI 在文字裡做的其他宣稱，要由你判斷。**

## 練習

### 練習 3.1　翻譯並證明

把「每個實數都有一個比它大的實數」翻譯成 Lean 陳述並證明。先在紙上寫出見證，再動手。

```lean
import Mathlib

example : sorry := by
  sorry
```

<details>
<summary>提示</summary>

外層是「對每個實數 x」，內層是「存在實數 y」。見證可以和 x 有關：給定 x，哪一個 y 一定比 x 大？要證明 `x < x + 1` 這類線性不等式，可以用 `linarith`。

</details>

<details>
<summary>解答</summary>

```lean
import Mathlib

example : ∀ x : ℝ, ∃ y : ℝ, x < y := by
  intro x
  exact ⟨x + 1, by linarith⟩
```

這和本章「沒有最大的自然數」的結構完全相同，只是型別從 `ℕ` 換成 `ℝ`。如果把量詞順序寫反成 `∃ y : ℝ, ∀ x : ℝ, x < y`，陳述就變成「有一個實數 y 比所有實數（包括 y 自己）都大」，那是假的，Lean 不會讓你證出來。

</details>

## 本章小結

- 每個邏輯符號都有兩個動作：引入（怎麼證明它）與消去（怎麼使用它）。卡住時先看目標與假設的最外層符號。
- 課本上的「分別證明兩邊」、「分情況」、「逆否」、「取 m = n + 1」，分別對應 `constructor`、`rcases`、`intro` 加函數套用、`⟨見證, 證據⟩`。
- 量詞順序決定數學意義。Lean 不會替你檢查翻譯是否忠實，這一步是你的責任。
