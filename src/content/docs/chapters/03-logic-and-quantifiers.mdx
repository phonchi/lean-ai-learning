## 本章目標

1. 對每個邏輯符號，知道「要證明它」與「手上有它」時分別用什麼 tactic。
2. 能處理 `∀` 與 `∃`，並看出量詞順序不同的兩個陳述意義完全不同。
3. 理解 constructive 與 classical 推理的差別，以及 Lean 中排中律的實際地位。
4. 練習把一句中文數學敘述翻譯成 Lean 陳述，並檢查翻譯是否忠實。

## 一張表：引入與消去

自然演繹（natural deduction）把每個邏輯符號的規則分成兩類：**引入**（如何證明它）與**消去**（如何使用它）。Lean 的 tactic 幾乎一對一對應這些規則。

| 符號 | 目標是它時（引入） | 假設中有它時（消去） |
| --- | --- | --- |
| `p → q` | `intro hp` | `apply h` 或 `h hp` |
| `p ∧ q` | `constructor` | `obtain ⟨hp, hq⟩ := h` |
| `p ∨ q` | `left` 或 `right` | `rcases h with hp \| hq` |
| `¬ p` | `intro hp`（目標變成 `False`） | `exact absurd hp h` 或 `exact h hp` |
| `False` | 通常無法直接證明 | `exact h.elim` 或 `contradiction` |
| `∀ x, P x` | `intro x` | `h a`（套用到特定的 `a`） |
| `∃ x, P x` | `use a`，再證 `P a` | `obtain ⟨x, hx⟩ := h` |

這張表值得反覆查閱。遇到卡住時，先問自己兩個問題：**目標的最外層符號是什麼？我手上有哪些假設的最外層符號可以拆？**

## 蘊含：`intro` 與 `apply`

當目標是 `p → q`，數學上我們說「假設 p」。Lean 中就是 `intro hp`：目標變成 `q`，假設中多了 `hp : p`。

當目標是 `r`，而你手上有 `h : q → r`，數學上我們說「要證 r，只需證 q」。Lean 中是 `apply h`：目標變成 `q`。這是**倒推**的寫法。

上一章看過的 `imp-trans` 區段，在 `intro` 之後用一行 `exact hQR (hPQ hP)` 直接交出整個 proof term。`imp-trans-steps` 區段證明同一個陳述，但把這一行拆成 `apply` 的倒推步驟：

<LeanCode file="Course/Logic.lean" region="imp-trans-steps" />

請在 VS Code 裡逐行觀察：`intro hp` 讓假設多了 `hp : P`、目標變成 `R`；`apply hqr` 把目標退回 `Q`；`apply hpq` 再退回 `P`；最後 `exact hp` 交出手上的證據。每一次 `apply`，都把目標換成所用蘊含的前提。

## 且：拆開與組合

`and-swap` 區段證明「p 且 q 推出 q 且 p」：

<LeanCode file="Course/Logic.lean" region="and-swap" />

這個證明在 `intro h` 之後只有一行：用 `h.2` 與 `h.1` **拆出**假設中 `∧` 的兩個證據，再用角括號把它們**組合**成目標的 `∧`，順序對調。同一件事也可以寫成更分步的 tactic 版本：

```lean
  obtain ⟨hp, hq⟩ := h
  constructor
  · exact hq
  · exact hp
```

先拆開假設，再用 `constructor` 分別交出兩邊。請注意一個習慣：每次拆開一個假設時，給它的兩個部分取有意義的名字，例如 `hp`、`hq`，之後讀 proof state 會輕鬆許多。

## 或：分情況

使用 `h : p ∨ q` 的唯一方式是**分情況**：情況一假設 p，情況二假設 q，兩種情況都要證出目標。`rcases h with hp | hq` 會產生兩個目標。

要**證明** `p ∨ q`，則要選一邊：`left` 讓目標變成 `p`，`right` 讓目標變成 `q`。選錯邊不會報錯，只會讓你卡在一個證不出來的目標上。這時請回頭想：數學上，到底是哪一邊成立？

## 非與矛盾

`¬ p` 被定義為 `p → False`。所以要證明 `¬ p`，就是 `intro hp`，然後證明 `False`，也就是推出矛盾。

`False` 是沒有證明的命題，因此你不會「直接證明 False」，而是從互相衝突的假設中得到它：如果同時有 `hp : p` 與 `hnp : ¬ p`，那麼 `hnp hp : False`。反過來，如果手上已經有 `False` 的證明，任何目標都可以由它得到（「從矛盾可以推出一切」）。

## 量詞

`∀ x : α, P x` 的證明，在 Lean 中就是一個函數：給任意 `x`，回傳 `P x` 的證明。所以 `intro x` 的意思是「任取一個 x」。

反過來，**使用**一個全稱假設，就是把這個函數套用到你指定的元素上。`quantifiers` 區段示範的就是這件事：已知每個 `x` 都滿足 `P`，把 `h` 套用到 `a`，得到 `P a`。

<LeanCode file="Course/Logic.lean" region="quantifiers" />

`∃ x : α, P x` 的證明，是一對：一個具體的見證 `a`，加上 `P a` 的證明。所以 `use a` 的意思是「取 x 為 a」，接著證明 `P a`。使用一個存在的假設時，`obtain ⟨x, hx⟩ := h` 的意思是「設 x 為那個滿足條件的元素」。課程範例檔沒有存在量詞的例子，練習 3.3 會讓你親手用 `use`。

### 量詞順序是翻譯中最常見的錯誤

比較以下兩句：

- 「對每個自然數 n，都存在 m 使得 n 小於 m。」寫成 `∀ n : ℕ, ∃ m : ℕ, n < m`。這是真的：取 m = n + 1。
- 「存在 m，使得對每個自然數 n，n 小於 m。」寫成 `∃ m : ℕ, ∀ n : ℕ, n < m`。這是假的：沒有最大的自然數。

兩句只差了量詞的順序，意義卻相反。AI 在翻譯數學敘述時，偶爾會混淆這類順序，尤其是原文用口語寫成「對所有 n 都有某個 m」這類模糊句式時。**檢查量詞順序是你的工作**，Lean 無法替你做：兩個陳述在 Lean 中都是合法的命題，只是其中一個證不出來。

## Constructive 與 classical：關於排中律

排中律說：對任何命題 p，`p ∨ ¬ p` 成立。在一般數學課上，我們理所當然地使用它，例如反證法。

從上面「或」的規則來看，證明 `p ∨ ¬ p` 需要**選一邊**並交出證據。對一個任意的、我們一無所知的 p，只用引入與消去規則，無法決定該選哪邊。這就是 **constructive**（構造式）邏輯的觀點：只用這些基本規則，排中律推不出來。

但這**不代表 Lean 不能證明排中律**。Lean 的標準函式庫提供 `Classical.em : ∀ p, p ∨ ¬ p`，它是由 `Classical.choice` 等標準公理推得的定理。mathlib 的數學大量使用 classical 推理，`by_contra`（反證法）與 `by_cases`（對任意命題分情況）也都可以直接使用。

所以正確的說法是：

- 在不使用 classical 公理的片段中，排中律不可證。
- Lean 加入了 `Classical.choice` 等公理後，排中律是一個定理，正常數學工作可以放心使用。
- 用了這些標準公理，`#print axioms` 會列出 `Classical.choice`，這**不是**作弊的跡象。

<LeanCode file="Course/VideoPractice.lean" region="double-negation" />

第一個方向：已知 `hP : P`，若再收到 `hNotP : P → False`，套用 `hNotP hP` 就得到矛盾。反方向面對任意命題時，這裡使用標準古典定理 `Classical.byContradiction`，不是另加一條自訂公理。

請在自己的練習檔先寫 `import Course.VideoPractice`，再查詢兩個定理：


讀出實際依賴，說明為什麼兩份證明使用的基礎不同。`P ∨ ¬P` 在 Lean 的標準古典基礎下也可由 `Classical.em` 得到；不能把「構造式片段中不可證」說成「Lean 不能證明」。

## 練習

### 練習 3.1　或的交換

證明 `p ∨ q → q ∨ p`。

```lean
example (p q : Prop) : p ∨ q → q ∨ p := by
  sorry
```

<details>
<summary>提示一</summary>

先 `intro h`。現在手上有一個「或」，該做什麼？

</details>

<details>
<summary>提示二</summary>

`rcases h with hp | hq` 之後有兩個目標。第一個目標中你有 `hp : p`，要證 `q ∨ p`：該選左邊還是右邊？

</details>

<details>
<summary>解答</summary>

```lean
  intro h
  rcases h with hp | hq
  · right
    exact hp
  · left
    exact hq
```

`·` 用來聚焦在其中一個目標上，讓結構清楚。也可以把 `right` 加 `exact hp` 合併成一行 `exact Or.inr hp`。

</details>

### 練習 3.2　否定的使用

證明 `(p → q) → ¬ q → ¬ p`（逆否）。

<details>
<summary>提示</summary>

`¬ p` 就是 `p → False`。連續 `intro` 三次之後，目標是 `False`。手上的哪兩個東西可以組成矛盾？

</details>

<details>
<summary>解答</summary>

```lean
example (p q : Prop) : (p → q) → ¬ q → ¬ p := by
  intro hpq hnq hp
  exact hnq (hpq hp)
```

注意這個證明沒有用到排中律；反過來的方向 `(¬ q → ¬ p) → (p → q)` 則需要 classical 推理。

</details>

### 練習 3.3　翻譯並判斷真假

把「有一個實數 x，使得對所有實數 y，x 小於等於 y 的平方」翻譯成 Lean 陳述，判斷真假，並說明哪一個見證可以用。

<details>
<summary>提示</summary>

先寫出量詞順序：外層是 `∃ x : ℝ`，內層是 `∀ y : ℝ`。y 的平方最小可以是多少？

</details>

<details>
<summary>解答</summary>

`∃ x : ℝ, ∀ y : ℝ, x ≤ y ^ 2`。這是真的，取 x = 0，因為任何實數的平方都不小於 0。在 Lean 中可以 `use 0`，接著 `intro y` 並用 mathlib 的 `sq_nonneg y` 收尾。`use` 與 `sq_nonneg` 都來自 mathlib，所以練習檔開頭需要有 `import Mathlib`（或更精確的 mathlib import）（[第 5 章](../05-mathlib/) 會介紹如何找到這類引理）。如果把量詞順序顛倒成 `∀ y, ∃ x, ...`，也是真的，但意義比較弱：x 可以隨 y 改變。

</details>
