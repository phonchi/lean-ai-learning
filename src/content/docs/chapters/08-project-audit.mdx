## 本章目標

1. 能對一個 Lean 定理做完整查核，並寫成一份簡短的查核紀錄。
2. 辨認常見的「看似正確的錯誤翻譯」：型別、量詞、截斷運算、矛盾假設。
3. 會用 `#print axioms` 與文字搜尋確認依賴，並正確解讀結果。
4. 為自己的形式化寫一段不依賴 Lean 的數學說明。

## 為什麼需要查核

到這裡，你已經看過很多次這句話：**Lean 只保證證明了檔案中寫的陳述**。這一章把它變成一套具體的流程。當你和 agent 合作時，查核尤其不能省：agent 的工作是讓檔案通過檢查，而你的工作是確認「通過檢查的東西就是你要的東西」。

查核分三部分，順序很重要：先看**原題**，再看**依賴**，最後看**最終檔案**。如果陳述就錯了，後兩步再完美也沒有意義。

## 第一部分：原題

把原題（課本、作業、論文中的敘述）與 Lean 陳述並排，逐項比對。

### 1. 物件與型別

原題的變數是整數、實數、還是自然數？在 Lean 中這是不同的陳述。例如「對所有 x，x 的平方大於等於 x」在 `ℕ` 上為真，在 `ℝ` 上為假（取 x = 1/2）。

### 2. 量詞

每個變數是「對所有」還是「存在」？順序是否正確？[第 3 章](../03-logic-and-quantifiers/) 已經看過 `∀ ∃` 與 `∃ ∀` 的差別。另一個常見問題是**隱含的量詞**：Lean 定理括號中的參數，例如 `(n : ℕ)`，相當於「對所有 n」。

### 3. 假設

原題的每一個前提，Lean 中都有嗎？Lean 中有沒有**原題沒有的**假設？多出來的假設會讓陳述變弱。最極端的情況是假設彼此矛盾，例如同時假設 `0 < x` 與 `x < 0`：此時**任何結論**都能被證明，因為從矛盾可以推出一切。這樣的定理會通過 Lean，但毫無內容。

### 4. 運算的實際定義

Lean 中有幾個運算的定義和日常數學不同，它們是為了讓函數處處有定義而做的選擇：

- `ℕ` 上的減法會截斷：`2 - 5 = 0`。
- `ℕ` 與 `ℤ` 上的除法取整數部分：`7 / 2 = 3`。
- `ℝ` 上除以零定義為零：`x / 0 = 0`。

所以一個包含除法的陳述，如果原題隱含「分母不為零」，Lean 陳述可能需要明確加上這個假設；反過來，若 Lean 陳述在分母為零時「碰巧成立」，也要確認這不是你想表達的意思。

### 5. 用小例子檢驗

挑幾個具體值，例如 n = 0、1、2 或空列表，手算原題與 Lean 陳述的兩邊。如果結果不一致，翻譯就有問題。這是**檢查翻譯**的工具，不是證明。

## 第二部分：依賴

### `#print axioms`

對每個主要定理執行：

```lean
#print axioms 定理名稱
```

解讀方式：

- 出現 `sorryAx`：證明中（或它引用的某個引理中）仍有 `sorry`。**未完成。**
- 出現不認識的名字，而且它是在你的專案中用 `axiom` 宣告的：這是自訂公理，等於「假設它成立」。除非課程明確允許，否則視為**未完成**。
- 只有 `propext`、`Classical.choice`、`Quot.sound`：這是 Lean 與 mathlib 的標準公理，正常。
- 「does not depend on any axioms」之類的訊息：完全不依賴公理，也正常。

### 定義是否被動過

如果原題涉及自訂的 `def`（例如自己定義的數列），請確認定義本身也和原題一致，而且在合作過程中沒有被修改。改定義和改陳述一樣，都是在改題目。

### 文字搜尋

在專案目錄中搜尋 `sorry`、`admit`、`axiom` 這幾個字（VS Code 的全域搜尋即可）。課程的練習檔原本就有 `sorry`，所以搜尋結果要逐一確認是否都在預期之外的地方。

## 第三部分：最終檔案

1. **儲存並實際檢查你交出的檔案**。在專案根目錄對每個練習檔執行 `lake env lean Exercises/檔名.lean`，閱讀完整輸出並記下 exit code。成功結束不代表沒有 `sorry`，要確認輸出中沒有 sorry 警告。`lake build` 只建置課程的參考範例庫 `Course/`，**不會**檢查 `Exercises/`，所以不能用它驗收練習；它適合在你修改了 `Course/` 中的檔案後使用。
2. **差異檢查**。若專案在 Git 中，用 `git diff` 確認合作過程中陳述、定義、import 都沒有被改動；若不在 Git 中，與原始下載的檔案比對。
3. **可讀性**。刪除留在檔案中的 `exact?`、`simp?` 等搜尋指令，換成它們建議的結果；這些指令留在檔案中雖然可能不會報錯，但每次都會重新搜尋。

## 數學說明

最後，為每個主要定理寫一段**不提 Lean 的**數學說明：陳述是什麼、證明的主要想法是什麼、哪一步最關鍵。如果你寫不出來，代表你還沒真正理解這個證明，不論它是誰寫的。

## 範例：查核前 n 個奇數和

以 [第 4 章](../04-induction-and-sums/) 的 `odd-sum` 為例：

<LeanCode file="Course/Induction.lean" region="odd-sum" />

一份查核紀錄可以這樣寫：

- **原題**：前 n 個正奇數的和等於 n²。
- **型別**：n 為自然數；n = 0 時兩邊皆為 0，原題中「前 0 個奇數的和」按慣例為空和 0，一致。
- **量詞**：對所有 n，由參數 `(n : ℕ)` 表示。
- **索引**：`Finset.range n` 是 0 到 n − 1，第 i 項是 2i + 1，所以涵蓋 1, 3, ..., 2n − 1，共 n 項。手算 n = 3：1 + 3 + 5 = 9。一致。
- **假設**：無額外假設。
- **依賴**：執行 `#print axioms` 後，把**實際輸出**貼在這裡，並註明其中是否有 `sorryAx`。
- **數學說明**：歸納法；步驟中把最後一項 2n + 1 拆出，得到 n² + 2n + 1 = (n + 1)²。

注意「依賴」那一欄：查核紀錄只能寫你實際執行看到的結果。

## 練習

### 練習 8.1　找出翻譯問題

以下每一個 Lean 陳述都想翻譯「對所有實數 x，若 x 大於 0 則 x 加上 x 的倒數至少為 2」。指出各自的問題。

```lean
-- (a)
theorem a1 (x : ℕ) (hx : 0 < x) : 2 ≤ x + 1 / x := by sorry
-- (b)
theorem a2 (x : ℝ) : 2 ≤ x + 1 / x := by sorry
-- (c)
theorem a3 (x : ℝ) (hx : 0 < x) (h : x < 0) : 2 ≤ x + 1 / x := by sorry
```

<details>
<summary>提示</summary>

分別檢查：型別、假設是否缺少、假設是否矛盾。對 (a)，算一下 x = 2 時 `1 / x` 在 `ℕ` 中是多少。

</details>

<details>
<summary>解答</summary>

(a) 型別錯：在 `ℕ` 中 `1 / x` 對 x 大於 1 時為 0，陳述的意義完全不同（而且 x = 2 時右邊是 2，碰巧成立，但這不是原題）。(b) 缺少 x 大於 0 的假設：x = −1 時右邊是 −2，陳述為假。(c) 假設矛盾：任何結論都能證，這個定理沒有內容。正確的翻譯應是在 `ℝ` 上、只帶 `0 < x` 這一個假設。

</details>

### 練習 8.2　解讀 `#print axioms`

以下三種輸出（示意）分別代表什麼？

1. 依賴清單中有 `propext`、`Classical.choice`、`Quot.sound`。
2. 依賴清單中有 `sorryAx`。
3. 依賴清單中有 `my_key_lemma`，而專案中有一行 `axiom my_key_lemma : ...`。

<details>
<summary>解答</summary>

1. 正常，只用了標準公理。2. 某處仍有 `sorry`，未完成。3. 關鍵步驟是被「假設」而非被證明，未完成；除非原題本來就是「在這個公理下」的命題，而且這件事有清楚寫明。

</details>
